# Render the selected visualization in the cloud

Type: grilling
Status: resolved
Blocked by: 08, 24, 28, 57

## Question

Where does the video come from now that the product no longer selects a pre-provisioned clip, and how is the existing `Sound-Visualization-Kaleidoscope-effect` project used by the backend?

## Answer

The Cloud Media Service generates one visualization video for every uploaded Shared Sound by reusing the checked-in `Sound-Visualization-Kaleidoscope-effect/particle-field` WebGL2 renderer. There is no Preset Video pool and no user video upload in the competition path.

The renderer gains a headless production mode that:

- accepts a deterministic Audio Feature Timeline derived from the normalized source audio instead of requesting microphone access;
- accepts an immutable visual seed derived from `content_id`;
- hides all recording, device, and debug controls;
- renders to a fixed 480x320 canvas;
- accepts explicit frame index and media time rather than reading `performance.now()`;
- renders exactly `ceil(duration_seconds * 10)` ordered frames for the authoritative normalized duration;
- exports each completed frame through a Canvas/WebGL readback seam to the backend process.

The backend runs the built renderer in Headless Chromium and pipes ordered raw or lossless frames directly to FFmpeg. FFmpeg produces the constrained fast-start H.264 MP4 required by `t5ai-h264-mp3-v1`. The normalized sound remains a separate `audio.mp3`; it is not multiplexed into `video.mp4`.

The [headless cloud rendering prototype](57-prototype-headless-cloud-rendering.md) proved that Chromium with ANGLE/SwiftShader can render the existing WebGL2 field and produce a valid constrained H.264 output. It also proved that real-time `requestAnimationFrame + canvas.captureStream + MediaRecorder` is not acceptable: two identical runs matched zero decoded frames and an eight-second source produced an 8.3-second output. Production therefore must use explicit frame stepping and must not use MediaRecorder.

The backend computes the Audio Feature Timeline from deterministic PCM generated by FFmpeg. The timeline may be retained as a private processing artifact until publication or recomputed from the permanently retained source, but it is not exposed to Trigger, Playback, or users.

Reimplementing the visualization in Python, replacing its shaders, rendering on the phone, adding multiple selectable visual styles, and using a pre-rendered fallback video are outside the competition scope.
